# 架构说明

## 1. 分层

```
┌──────────────────────────────────────────────────────────────┐
│ MCP 客户端（Claude Desktop / Cursor / Doubao agent / 其他）  │
└───────────────▲──────────────────────────────────────────────┘
                │ MCP tools (JSON-RPC over stdio)
┌───────────────┴──────────────────────────────────────────────┐
│ server.py            FastMCP 实例，工具注册与参数校验          │
├──────────────────────────────────────────────────────────────┤
│ engine.py            纯编排层：巡检 / 审题 / 作答 / 报告聚合   │
├───────────────┬──────────────────────┬───────────────────────┤
│ platform.py   │ operator.py           │ report.py / solver.py  │
│ 只读 REST 客户端│ 页面 UI 写入与状态复核 │ 报告渲染 / 答案规范化  │
├───────────────┴──────────────────────┴───────────────────────┤
│ browser.py           Playwright 持久化会话（storage_state）    │
└──────────────────────────────────────────────────────────────┘
                │ Chromium (headed / headless)
┌───────────────┴──────────────────────────────────────────────┐
│ 青软 U+ 平台 https://www.eduplus.net                          │
└──────────────────────────────────────────────────────────────┘
```

## 2. 模块职责

| 模块 | 职责 | 不做什么 |
| --- | --- | --- |
| `config.py` | 加载 `courses.json`、路径解析、默认课程清单 | 不直接访问浏览器或网络 |
| `models.py` | 课程 / 作业 / 题目 / 实验数据模型、题型与状态枚举、HTML 清洗 | 不含网络请求 |
| `browser.py` | 启动 Playwright、持久化登录态、页面内同源 GET、登录态健康检查 | 不解析业务字段 |
| `platform.py` | 课程、作业、题目只读接口封装，返回模型对象 | 不做页面点击与提交 |
| `operator.py` | 打开作答页、填客观题、回读核对、提交作业、附件上传、实验状态解析 | 不做题目判断与答案生成 |
| `solver.py` | 题目审题包生成、模型答案解析与按题型规范化、规则兜底钩子 | 不内置题库 |
| `report.py` | 巡检快照聚合、Markdown 渲染、报告落盘 | 不发起网络请求 |
| `engine.py` | 跨模块编排，MCP 工具与 CLI 共用同一套业务流程 | 不暴露浏览器细节 |
| `server.py` | FastMCP 工具薄封装、懒加载单例 | 不写业务规则 |

## 3. 关键设计决策

### 3.1 读走 API，写走页面

- 课程、作业、题目元数据与题干选项通过 REST 接口批量读取，速度快、结构稳定。
- 答案保存与作业提交走真实作答页 UI：平台写接口的鉴权与提交载荷未完全逆向，且题目/选项可能乱序（`optionDisordered=1`、`questionDisordered=1`），页面操作与真人路径一致，对前端改版的容错性更好。
- 页面按钮文案是提交状态的唯一权威来源，接口 `submitTask` 仅作粗筛（见 `docs/api-mapping.md` 第 5 节）。

### 3.2 答案由客户端模型产生，服务端不养题库

- `uplus_inspect_homework` 返回结构化审题包（题干、选项、知识点、题型提示）。
- MCP 客户端模型（Claude、Cursor agent、Doubao agent 等）完成推理，返回 `{question_id: answer}`。
- `engine` 只做格式校验、按题型规范化与页面填写；`solver.rule_based_answer` 预留课程规则钩子，默认返回 `None`，避免在未复核的情况下凭规则猜答案。

### 3.3 自动 / 接管边界

| 可自动 | 必须人工接管 |
| --- | --- |
| 单选、多选、判断、填空 | 简答题、编程题、实验报告、成果物 |
| 已答题目状态复核 | 小组分工 PPT / 附件上传（素材缺失无法编造） |
| 客观题回读核对与提交 | 已截止作业（不再尝试补交） |

### 3.4 登录态持久化

- `storage_state.json` 保存 Cookie 与本地存储快照，首次登录由 `scripts/login.py` 可见浏览器完成。
- MCP 服务长驻进程内懒启动浏览器；`uplus_close` 显式释放。
- 会话失效时工具抛出 `AuthExpiredError`，不反复重试，提示重新登录。

## 4. 数据流：一次定时巡检

1. CLI 或 `uplus_patrol` 启动引擎，检查登录态。
2. 遍历配置课程：拉取作业列表；接口标记未提交的作业逐份打开页面复核真实状态。
3. 对未提交且未过期的作业拉取题目：可答题型汇总为 answer brief；主观题、附件题进入 takeover 清单。
4. 读取每门课实验栏目，未提交实验进入 takeover 清单。
5. 聚合快照渲染 Markdown 报告落盘 `reports/patrol_YYYYMMDD_HHMM.md`。
6. 返回统计摘要、待答 brief、待接管清单与报告路径。
7. 后续 MCP 会话读取 brief，模型作答后调用 `uplus_answer_homework` 填写并提交。

## 5. 测试边界

- 单元测试覆盖模型解析、配置加载、答案规范化等纯逻辑。
- 浏览器与平台交互在沙箱环境以只读巡检验证；写操作（提交、上传）必须在真实课程截止期内、由授权账号执行。
