[3][Normal] （1）理解 A* 算法的基本原理与核心思想：以 f(n)=g(n)+h(n) 作为节点的评价函数，在状态空间中有序扩展节点，既考虑从起点到当前节点已付出的实际代价 g(n)，又估计从当前节点到目标还需付出的代价 h(n)。
（2）掌握 A* 算法在路径规划中的应用：完成栅格地图建模、邻居扩展、Open 表与 Close 表维护，输出从起点到终点的最优路径。

[5][Normal] 在 10×10 栅格地图上进行 A* 路径规划实验。地图障碍占比 20%，起点为左上角 (0,0)，终点为右下角 (9,9)，随机种子固定为 20261113 以保证结果可复现。实验内容包括：

2. A* 主循环：用优先队列维护 Open 表（按 f 值升序），用集合维护 Close 表（已扩展节点），每轮弹出 f 最小节点并扩展其邻居；
3. 状态空间记录：每扩展一步记录节点坐标、g 值、h 值、f 值以及当时 Open 表与 Close 表的规模，用于 Open/Close 表分析；

5. 全局参数调整：改变障碍物比例与地图规模，观察对搜索过程与结果的影响。

[8][Heading 2] 实验实现
[9][Normal] 一、算法伪代码描述（A* 主循环）

输入：栅格地图 grid，起点 start，终点 goal，启发式函数 h
输出：最优路径 path 及各项搜索指标
1. g[start] ← 0；f[start] ← h(start)；Open ← {start}；Close ← ∅
2. while Open 非空：
3.     cur ← Open 中 f 值最小的节点
4.     将 cur 从 Open 移入 Close
5.     if cur = goal：回溯 parent 得到 path，结束
6.     for each 邻居 nbr of cur（未被障碍占据）：
7.         tentative_g ← g[cur] + cost(cur, nbr)
8.         if tentative_g < g[nbr]：
9.             parent[nbr] ← cur；g[nbr] ← tentative_g；f[nbr] ← g[nbr] + h(nbr)
10.            将 nbr 压入 Open
11. return 无解（Open 表耗尽仍未到达 goal）

二、核心实现代码（Python 3.12）

def a_star(grid, start, goal, hfun, nbrs):
    g = {start: 0.0}
    parent = {}
    open_heap = [(hfun(*start), 0.0, start)]   # (f, g, node)
    closed = set()
    while open_heap:
        f, cur_g, cur = heapq.heappop(open_heap)
        if cur in closed:
            continue
        closed.add(cur)
        if cur == goal:
            break
        r, c = cur
        for nr, nc, cost in nbrs(r, c, len(grid), len(grid[0])):
            if grid[nr][nc] == 1:
                continue
            ng = cur_g + cost
            if ng < g.get((nr, nc), float('inf')):
                g[(nr, nc)] = ng
                parent[(nr, nc)] = cur
                heapq.heappush(open_heap, (ng + hfun(nr, nc), ng, (nr, nc)))
    path, node = [], goal
    while node != start:          # 沿父指针回溯
        path.append(node)
        node = parent[node]
    path.append(start)
    return path[::-1]

三、启发式函数与邻居集合
欧氏距离：h(r,c) = sqrt((r-gr)^2 + (c-gc)^2)，8 邻域下直行代价 1、对角代价 √2，该启发式可采纳且一致。
曼哈顿距离：h(r,c) = |r-gr| + |c-gc|，对 4 邻域是可采纳的紧致估计；在 8 邻域下不再一致（对角移动一步曼哈顿距离减少 2，而实际代价仅 √2），容易高估。
邻居集合：8 邻域包含上下左右与四个对角线方向；4 邻域仅包含上下左右四个方向。

五、结果分析与复杂度
（1）势能与路径代价：8 邻域下直行代价 1、对角代价 √2，沿对角线方向的路径代价低于纯 4 邻域折线路径，因此 8 邻域得到代价 13.314 的最优路径，而 4 邻域只能得到代价 18.000 的折线路径，路径长度由 11 增加到 19。
（2）启发式紧致度：4 邻域下改用曼哈顿距离后，扩展节点数由 59 降到 53、Open 表峰值由 19 降到 17。曼哈顿距离对 4 邻域是可采纳且紧致的估计，其估计值更接近真实剩余代价，能更快地把搜索收敛到终点附近。
（3）8 邻域下曼哈顿距离的高估问题：h 由欧氏距离改为曼哈顿距离后，扩展节点数从 13 降到 11、耗时由 0.14 ms 降到 0.05 ms，但该启发式在对角移动时每步最多高估 (2-√2) ≈ 0.586，属于不可采纳启发式，只在本次小规模地图上恰好仍得到相同代价（13.314）的最优路径；地图更大、障碍更密集时不保证最优。
（4）时间复杂度：设扩展节点数为 N、每个节点的平均出度为 b，维护 Open 表使用二叉堆，单次插入为 O(log N)，故总复杂度为 O(N b log N)；空间复杂度为 O(N)，主要为 Open/Close 表与 g、parent 字典的存储，其中 g 字典记录每个节点当前的最优代价，parent 字典用于路径回溯。
（5）参数敏感性：把障碍占比从 20% 提高到 30%~40% 时，可通行路径被切断的概率上升，Open 表会积累更多 f 值相近的节点，扩展节点数显著增加；地图从 10×10 扩大到 20×20 后，节点规模变为原来的 4 倍，而 Open 表操作的 log 因子只缓慢增长，实际耗时随扩展节点数近似线性上升。

[24][Heading 2] 实验总结
[25][Normal] 1. A* 的核心在于 f(n)=g(n)+h(n) 的排序机制：g 保证已经付出的代价不计入重复，h 提供向目标方向的指引。只要 h 是可采纳的（不高估真实剩余代价），A* 输出的路径就是最优的。
2. 启发式越紧致，搜索越快。实验数据表明：4 邻域下曼哈顿距离比欧氏距离更快收敛（扩展节点 53 对 59）；而 8 邻域下曼哈顿距离虽然更快（11 对 13），但它对角移动时高估代价、不再满足一致性，属于用最优性换速度的取舍，地图更复杂时会暴露出次优路径的问题。
3. 邻域定义直接决定路径形态与代价：8 邻域允许对角移动，路径更平滑、代价更低（13.314 对 18.000），但需注意对角穿越两个相邻障碍物缝隙时的切角问题，工程实现中通常增加“对角移动时两条相邻边均须可通行”的约束。
4. 关键难点在于 Open 表与 Close 表的正确维护：同一个节点可能被多次以不同 g 值压入堆中，必须在弹出时判重（已在 Close 表中则跳过），否则会出现重复扩展与指标虚高；父指针 parent 的更新必须在 g 值真正变小时进行，否则回溯得到的路径不是最优。
5. 调试体会：初期把 f 值直接作为堆的排序键而丢掉了 g 值，导致弹出节点后无法判断当前路径的实际代价；把堆元素设计为 (f, g, node) 三元组后问题解决。这类“数据结构与算法状态不一致”的错误在启发式搜索中很常见，需要在每一步扩展时打印 g/h/f 三个值来自查。
6. 本实验的局限：地图为静态栅格、邻居固定、未考虑动态障碍与运动学约束；后续可扩展到 Dijkstra、JPS、双向 A* 以及真实二维连续空间（如机器人导航中的栅格化地图）。
