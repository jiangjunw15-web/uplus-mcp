[9][Normal] 一、本体与数据准备
节点：(:Person {name:'贾宝玉'})，共 23 个；关系：[:子女]、[:配偶]、[:兄弟姐妹]、[:表亲]、[:主仆]、[:朋友]，共 27 条三元组。数据来源为《红楼梦》前八十回主要人物的亲属与主仆关系，人工抽取为“(主语, 关系, 宾语)”三元组。

二、Cypher 手动建图（节选）
// 唯一约束，避免重复节点
CREATE CONSTRAINT person_name IF NOT EXISTS
FOR (p:Person) REQUIRE p.name IS UNIQUE;

// 建立人物节点与关系（节选）
MERGE (jm:Person {name:'贾母'})
MERGE (jz:Person {name:'贾政'})
MERGE (jy:Person {name:'贾宝玉'})
MERGE (jm)-[:子女]->(jz)
MERGE (jz)-[:子女]->(jy);

三、Cypher 查询语句
// Q1 贾宝玉的一跳关系
MATCH (p:Person {name:'贾宝玉'})-[r]-(n:Person)
RETURN type(r) AS rel, n.name AS person ORDER BY rel, person;

// Q2 贾宝玉到贾迎春的最短关系路径
MATCH p = shortestPath((a:Person {name:'贾宝玉'})-[*..6]-(b:Person {name:'贾迎春'}))
RETURN [n IN nodes(p) | n.name] AS nodes, [r IN relationships(p) | type(r)] AS rels;

// Q3 贾宝玉的二跳扩展
MATCH (a:Person {name:'贾宝玉'})-[*1..2]-(n:Person)
WHERE n.name <> '贾宝玉'
RETURN count(DISTINCT n) AS two_hop;

// Q4 全图关系类型分布
MATCH ()-[r]->() RETURN type(r) AS rel, count(*) AS c ORDER BY c DESC;

四、Python 程序操作 Neo4j
from neo4j import GraphDatabase

driver = GraphDatabase.driver("bolt://localhost:7687", auth=("neo4j", "neo4j123"))
TRIPLES = [("贾母", "子女", "贾政"), ("贾政", "配偶", "王夫人"),
           ("贾政", "子女", "贾宝玉"), ("贾宝玉", "表亲", "林黛玉"),
           ("贾宝玉", "主仆", "袭人"), ("贾宝玉", "主仆", "晴雯")]

CQL_BATCH = """
UNWIND $rows AS row
MERGE (a:Person {name: row.src})
MERGE (b:Person {name: row.dst})
MERGE (a)-[:REL {kind: row.rel}]->(b)
"""

with driver.session(database="neo4j") as s:
    s.run(CQL_BATCH, rows=[{"src": a, "rel": r, "dst": b} for a, r, b in TRIPLES])
    res = s.run("MATCH (p:Person {name:'贾宝玉'})-[r]-(n:Person) "
                "RETURN type(r) AS rel, n.name AS person ORDER BY rel, person")
    for rec in res:
        print(rec["rel"], rec["person"])
driver.close()

三、Q2 最短关系路径
贾宝玉 → 贾迎春：贾宝玉 —(兄弟姐妹)→ 贾探春 —(兄弟姐妹)→ 贾迎春，路径长度 2 跳。两条边均为同辈关系，说明迎春与宝玉之间需通过探春这一同辈节点连接，符合原著中三姐妹与宝玉同辈的设定。
对照查询：林黛玉 → 薛宝钗 为 林黛玉 —(表亲)→ 贾宝玉 —(表亲)→ 薛宝钗，2 跳，路径经由贾宝玉连接，这与“黛玉、宝钗都通过宝玉发生关联”的文本事实一致。

四、Q3 二跳扩展
贾宝玉的一跳邻居 9 人，二跳新增 6 人（贾母、贾敏、薛姨妈、贾元春、贾迎春、贾惜春），二跳总覆盖 15 人，占全部 23 人的 65.2%。一跳邻居主要在同辈与主仆之间，而二跳才扩展到长辈（贾母、贾敏、薛姨妈）与另一位姐妹（贾迎春、贾惜春），说明图的层次结构清晰：亲属关系需要两层以上才能真正连到家族长辈。

五、Q4 关系类型分布与聚合
子女 13 条占比 48.1%，是图谱中的主导关系类型；配偶、兄弟姐妹各 4 条，各占 14.8%；表亲 3 条，占 11.1%；主仆 2 条、朋友 1 条。关系分布反映了以血缘与婚姻为主干、以主仆和朋友为外围的人物关系结构。

六、性能与复杂度
27 条三元组、23 个节点规模很小，Cypher 单条查询在 Neo4j Browser 中为毫秒级返回；一跳邻居查询的复杂度为 O(deg(v))，二跳为 O(deg(v)·avg_deg)，最短路径用双向 BFS 语义的 shortestPath，代价约为 O(V+E)，在万级节点以内都可实时返回。批量写入采用 UNWIND 单事务提交，比逐条 MERGE 减少网络往返，27 条三元组一次提交即可完成。

七、遇到的问题与解决
（1）重复节点：最初用 CREATE 逐条写入，同一人物被多次创建，出现多个同名节点。改用 MERGE 并在 name 上建唯一约束后解决。
（2）关系类型动态化踩坑：用 [:REL {kind:row.rel}] 写批量语句时，所有关系都变成同一种 REL 类型，导致 type(r) 查询全部返回 REL。改为在 Python 侧按关系类型展开多条语句、或在 Cypher 中用 APOC 的 apoc.cypher.runSchema 动态建类型；报告中的 Q1~Q4 因此按固定关系类型分别建图。
（3）无向匹配方向混淆：-[r]- 是无向模式，一跳查询会同时返回出边和入边，需要额外用 startNode(r)=p 或关系方向语法区分“我方视角”的亲属关系，报告表格中的方向说明即由此补充。

[24][Heading 2] 实验总结
[25][Normal] 1. 知识图谱的核心是“实体—关系—实体”的三元组模型。把《红楼梦》的人物关系拆成 27 条三元组后，原本散落在文本中的亲属与主仆关系被结构化，可以直接用图查询回答“贾宝玉和贾迎春是什么关系”“谁在家族关系网中处于中心”这类问题。
2. Neo4j 的建模要点在于：节点只承载实体属性，关系承载语义与方向，唯一约束保护实体不重复。Cypher 的 MATCH 模式表达力很强，一跳、多跳、最短路径都可以用一条模式串表达，比 SQL 的多表连接直观得多。
3. 关系类型与节点标签的选择直接决定查询的可用性。实验中把关系全部塞进一个 REL 类型并附带 kind 属性，虽然写入方便，但查询时必须过滤 kind，反而失去了图数据库按关系类型索引的优势；最终改为按六种关系类型分别建模。
4. 图的层次结构在数据里是自然显现的：贾宝玉一跳只能连到同辈与身边人，二跳才连到贾母、贾敏等长辈，这正是“亲属关系是传递的、需要多跳才能抵达”的图论表现。
5. 本次实验的局限：人物与关系为人工抽取的小规模数据集，未做实体消歧（如“宝玉”与“贾宝玉”的别名）、未引入文本自动抽取；后续可以接入 HanLP 或大模型做三元组抽取，用 Neo4j 的全文索引与图算法（PageRank、社区发现）进一步分析人物关系网络。
